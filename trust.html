Trust center

Security belongs in the work, not just the pitch.

We focus on practical controls, responsible disclosure and clear boundaries. We do not claim certifications we have not independently earned.

Engineering practices

Controls we design for.

Specific controls can vary by project, hosting platform and client requirements. They should be confirmed in the proposal or security questionnaire for each engagement.

Least-privilege access

Prefer role-based accounts and only the access needed for delivery. Avoid unnecessary sharing of master credentials.

MFA where supported

Use multi-factor authentication on critical delivery, hosting and administrative systems where the platform supports it.

Secrets management

Keep production secrets out of public repositories and client-side code; use environment or platform secret stores.

Dependency hygiene

Review dependencies, patch known issues and avoid adding packages without a clear need.

Secure transport

Production websites and APIs should use HTTPS/TLS, with secure headers appropriate to the application.

Change review & QA

Use review points, testing and deployment checks proportionate to project risk before production changes.

Responsible disclosure

Found a security issue?

Use VSN's published security contact so reports can be handled privately. Do not include sensitive customer data unless it is necessary to explain the issue.

Public security contact
Coordinated reporting

Security researchers should act in good faith, avoid privacy violations, service disruption or destructive testing, and allow reasonable time for investigation and remediation.

Client data

Security responsibilities are shared.

VSN can build and operate technical controls, but customers also control user permissions, source data, third-party accounts and their own legal/compliance obligations.

Scope

Define data types, environments, access needs and third-party processors before high-risk work begins.

Access

Use named accounts, MFA and revocation procedures instead of permanent shared credentials where possible.

Delivery

Separate test and production work, protect secrets and document high-impact configuration changes.

Handover

Rotate temporary access, transfer ownership and document ongoing operational responsibilities.

No unsupported certification claims.

This trust page describes VSN's intended engineering and delivery approach. It does not state that VSN is SOC 2, ISO 27001, PCI DSS or otherwise certified unless a valid certification is published separately.

Have security requirements?

Include hosting, data sensitivity, access, compliance and procurement requirements in the project brief so they can be scoped before development.
